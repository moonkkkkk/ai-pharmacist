## v0.4 迭代说明（本版变更总览）

本版把 PRD 对齐到已上线的 MVP 代码，主要变化如下，正文相应章节已同步更新：

1. **角色架构**：老人端/子女端不再分开展示，改为**合并页面 + 角色动态渲染**（同一页面用 `wx:if` 按角色显示不同内容），自定义 tabBar 5 个 tab。
2. **商业化**：MVP 阶段**全部功能免费**，暂不实现付费订阅/微信支付。原 v0.3 的免费/付费差异化内容保留为「规划（未实现）」，正文标注。
3. **AI 选型**：文案生成由通义千问改为 **DeepSeek（deepseek-chat）**；**TTS 语音播报本期未实现**；食物禁忌知识库检索未接入（字段预留）。
4. **用药频率**：由「每天/每周」扩展为「每天 / 每周 / 每 X 日一次（1-90 天）」。
5. **触达**：四级触达中 L1/L2/L4 已实现（订阅消息 + 通知子女），**L3 短信未接入**；级间隔统一为 10 分钟。
6. **数据表**：由 3 张表改为 4 张（新增 `bindings` 邀请码绑定表），字段大幅简化（详见第五章）。
7. **新增功能**：头像上传、手机号绑定、子女看板折线图、用药记录热力图、邀请码 + URL Link、演示数据生成（开发用）。

## v0.5 迭代说明（本版变更总览）

本版在 v0.4 全免费 MVP 基础上，落地「正式产品」的商业化最小闭环（模拟支付），主要变化如下，正文相应章节已同步更新：

1. **会员付费（模拟支付）**：新增 `subscribe` 云函数，点击「开通会员 / 续费」直接写入 `users.subscription_status = 'paid'`、`subscription_expire = now + 30 天`，价格 ¥9.9/月。因个人主体无法开通微信支付商户号，采用「点击即开通」的模拟支付（B 路线），未接入真实微信支付。
2. **付费功能边界（简化）**：会员专属功能 = **每周用药总结（周报）** + **打电话提醒**。其余（L1/L2/L4 订阅消息、AI 文案、看板、热力图、绑定家人等）全部免费。
3. **每周用药总结（周报）**：新增 `getWeeklySummary` 云函数，用 DeepSeek 把老人近 7 天用药情况生成一段给子女看的周报（≤80 字、只给生活化建议、不含医疗建议），子女端看板每个家人卡片内展示；未付费显示锁 + 点击开通。
4. **打电话付费墙**：看板「📞 打电话提醒」由免费改为付费，未付费点击直接弹开通会员弹窗。
5. **我的页会员卡片**：老人/子女「我的」页新增会员卡片，显示开通状态 / 到期时间，支持开通与续费。
6. **数据表**：`users` 表新增 `subscription_status`、`subscription_expire` 两个字段。

## 一、背景与目标

### 背景

中国 60 岁以上人口 2.97 亿（2023），75.8% 患有至少一种慢病，65% 存在多病共存（≥2 种慢病），日均服药 5-10 种。然而用药依从率不足 50%——一半的老人没有按时吃药。

核心矛盾不在医院，在"出院后"：多张处方散落在不同 HIS 系统、OTC 自购药无人把关、子女远程无法获知父母真实用药情况。慢病管理在"最后一公里"断裂了。

### 目标

打造一款面向慢病老人的 AI 用药提醒产品——用 AI 生成生活化的提醒文案和语音播报，让老人感觉"有人在关心我"而不是"机器在管我"，同时让远程子女能获知父母用药状态。

MVP 目标：30 天内跑通"提醒生成→四级触达→用户确认→子女通知"完整链路，获得 20 个种子家庭、D7 留存 ≥ 70%。

## 二、故事介绍

### 2.1 名词解释

| 术语 | 说明 |
|------|------|
| 小云 | AI 用药管家的名称，贯穿所有提醒文案 |
| 用药计划 | 用户录入的药品+时间+频次组合，是提醒触发的依据 |
| 生活化文案 | LLM 根据药品名、昵称、天气、禁忌生成的口语化提醒，≤80 字 |
| 护栏（Guardrails） | LLM 输出后的安全过滤层，拦截危险内容并替换为兜底文案 |
| 四级触达 | L1微信订阅消息 → L2微信二次提醒 → L3短信兜底 → L4子女通知 |
| 确认服药 | 老人收到提醒后点击"已吃药"，记录时间戳 |
| 漏服 | 提醒发送后累计未确认的状态 |

### 2.2 故事阐述

王建国，68 岁，退休车间主任，住在杭州。高血压 15 年，糖尿病 5 年，每天要吃 5 种药。早上 3 种、中午 1 种、晚上 1 种。

早上那顿他基本不会忘——几十年习惯了。但中午那顿经常漏，午睡一醒就忘了。上个月漏了 6 次午间药。

他儿子陈明在上海做后端开发，每天打电话问"爸，药吃了吗？"。王建国每次都回"吃了吃了"，但陈明知道——有几次肯定没吃，因为父亲的声音听起来刚睡醒。

去年王建国因为漏吃降压药，血压飙到 180，邻居送去了医院。陈明第二天才知道。

这就是 AI 云药师要解决的问题。

每天中午，王建国的微信弹出一条消息："王叔叔，午安。二甲双胍随餐吃刚刚好。今天外面 35 度，多喝点水，别中暑了。"他点一下绿色的"已吃药"按钮，陈明在上海的手机上就看到一个绿色的勾。

如果王建国午睡睡过头没看到微信，10 分钟后系统会再发一次微信。如果他还是没反应，一条短信会发到他手机上："王叔叔，12:00了，二甲双胍该吃了。——小云"。如果短信也没回——陈明会收到一条通知："您父亲的午间药（二甲双胍）尚未确认，建议您打个电话。"

王建国觉得"小云"像个关心他的老朋友，不是监控器。陈明不用每天打电话问了，但父亲漏服了他能及时知道。

### 2.3 价值分析

| 角色 | 现状 | 使用后 | 价值 |
|------|------|--------|------|
| 自理老人（王建国） | 凭记忆吃药，午间经常漏服 | AI 温柔提醒，点一下就行 | 有人提醒，但不受管控 |
| 半依赖老人（李秀兰） | 不会操作 App，全靠女儿盯 | 语音播报，零操作 | 不需要操作手机就能被提醒 |

| 复诊医生 | 凭老人自述判断用药依从性 | 获得真实用药数据 | 精准调整方案 |

### 4.2 Prompt 策略

**System Prompt 核心约束**：

1. 角色：温暖贴心的用药管家"小云"，服务对象是 65 岁以上慢病老人
2. 安全红线：绝对不能建议停药、改剂量、更换药品、补服药物
3. 准确性要求：药品名称、时间、剂量必须和输入严格一致
4. 语气要求：像家人在耳边温柔叮嘱，不使用"患者""您"等书面语
5. 字数限制：每次提醒 ≤ 80 字
6. 个性化：使用昵称称呼，如有食物禁忌必须提及，极端天气可加入关怀
7. 漏服约束：如果用户漏服，不要建议补服，只说"今天XX时间的药尚未确认"
8. 中文强制：药品名称必须使用中文通用名，英文输入请转换为中文通用名
9. 空值处理：如果天气为空，不要提及任何天气相关内容

**Few-Shot 覆盖场景**（4 个示例）：

| 场景 | 覆盖要点 |
|------|---------|
| 降压药 + 食物禁忌 | 昵称+药品名+禁忌提及+天气关怀+字数控制 |
| 降糖药 + 随餐服用 | 药品名+时机描述+无禁忌跳过 |
| 降脂药 + 晚间服用 | 晚间氛围+油腻禁忌+天气关怀 |
| 多药同时段服用 | 两个药品名都出现+简短提醒不过长 |

> 完整 Prompt 见 `03-prompts/reminder-prompt.md`

### 4.3 护栏规则

**硬性阻断**（命中即拦截，使用兜底模板）：

| 规则 | 检测方式 | 兜底文案 |
|------|---------|---------|
| G1：含"停药""减量""加量""补服""换药" | 关键词匹配（输入+输出双向） | "请遵医嘱服药，如有不适请咨询医生" |
| G2：药品名与输入不一致 | 字符串包含检查 | 用原始药品名重新生成 |
| G3：服用时间偏离超过5分钟 | 正则提取时间比对 | 用原始时间重新生成 |
| G4：输出为空或纯英文 | 长度+字符集检查 | 使用药品类别预设模板 |
| G5：含"可能""也许""不确定"等模糊词 | 关键词匹配 | 重新生成一次，仍不通过用模板 |
| G6：复述了输入中的危险指令 | 关键词匹配 | 拦截并使用兜底模板，不二次传播危险信息 |

**软性修正**：

| 规则 | 处理方式 |
|------|---------|
| 超过 80 字 | 截断到最后一个完整句号 |
| 使用"患者""您"而非昵称 | 替换为昵称 |
| 英文标点 | 替换为中文标点 |

**兜底模板**：

| 药品类别 | 预设模板 |
|---------|---------|
| 降压药 | {nickname}，{time}啦，降压药该吃了。记得{timing}服用哦。 |
| 降糖药 | {nickname}，{time}了，降糖药{timing}吃。按时吃饭，血糖稳稳的。 |
| 降脂药 | {nickname}，{time}啦，降脂药该吃了。{timing}服用最好。 |
| 其他 | {nickname}，{time}了，{drug_name}该吃了。{timing}服用哦。 |

**护栏执行流程**：

```
LLM 输出
    ↓
硬性阻断检查（G1-G6）→ 命中？→ 拦截，用替代文案
    ↓ 通过
软性修正检查 → 需要修正？→ 自动修正后放行
    ↓ 通过
原样输出给用户
```

**G1 双向拦截说明**：G1 不仅检查 LLM 输出，也检查用户输入。如果用户输入中含"停药""减量"等危险指令，输入侧先清洗移除后再传 LLM，输出侧再次检查——确保危险内容不出现也不被复述。

> 完整护栏设计见 `03-prompts/guardrails.md`

### 4.4 降级策略

#### AI 能力降级

| 异常场景 | 降级方案 | 用户感知 |
|---------|---------|---------|
| LLM API 超时（>3秒） | 跳过 LLM，直接使用兜底模板 | 收到提醒，无个性化（"王叔叔，8点了，降压药该吃了"） |
| LLM 连续 3 次被护栏拦截 | 使用兜底模板 | 同上 |
| TTS API 超时 | 仅发送文字提醒，不含语音 | 收到文字提醒，无语音播报 |
| 知识库查询失败 | 跳过食物禁忌提示 | 不提禁忌（不提好过乱提） |

#### 触达通道降级（四级递进）

```
用药时间到
  ↓
L1 微信订阅消息发送（AI文案）
  ↓ 10分钟未确认
L2 微信二次提醒
  ↓ 10分钟仍未确认（累计20分钟）
L4 子女漏服通知 → 子女打电话兜底
```

| 层级 | 通道 | 费用承担 | 免费版 | 付费版 | 预期累积触达率 |
|------|------|---------|--------|--------|-------------|
| L1 | 微信订阅消息 | 免费 | ✅ | ✅ | 60-70% |
| L2 | 微信二次提醒 | 免费 | ✅ | ✅ | 75-85% |
| L4 | 子女漏服通知（微信） | 免费 | ✅ | ✅ | 90-95% |
| L4' | 子女打电话提醒 | 免费（用户拨出） | ❌ | ✅ | ~100% |

**L3 短信不做**：短信兜底已由「L4 子女漏服通知 + 子女打电话」替代，未接入腾讯云 SMS。

**降级原则**：核心功能（提醒到达）不受影响，AI 是锦上添花。"到点提醒你吃药"这件事无论如何要完成。免费版用户也能收到 L1/L2/L4 提醒；「打电话提醒」是会员专属的兜底增强（无需系统成本，用户自己拨号）。

### 6.3 非页面端功能逻辑

#### 提醒触发引擎（定时任务）

```
云函数定时触发器每分钟执行一次 sendReminder
  → 先处理到期的「待服」记录（升级触达层级）
  → 再扫描 medication_plans
    → 判断当前时间 >= take_time（还没到点跳过）
    → 判断今天是否是服药日（每 X 日一次按 start_date 取模）
    → 检查该 plan 今天是否已生成过记录（防重复）
    → 未生成 → 触发 L1 提醒
```

#### 提醒发送流程（sendReminder）

```
到点 → 生成提醒文案（规则模板）→ 发送 L1 订阅消息
  → 写入 medication_logs（status=待服, level=1, next_remind_time=10 分钟后）
```

> 说明：AI 文案由 generateText 云函数单独生成（DeepSeek + 护栏 + 兜底模板），sendReminder 实际发送用的是规则模板文案 `记得吃药：{药名}（{时机}）`。两者为独立链路，本期未打通。

#### 四级触达递进流程（实际）

```
L1 到点 → 发订阅消息给老人 → 写日志（待服, level=1）
  ↓ 10 分钟未确认
L2 再发订阅消息 → level=2
  ↓ 再 10 分钟未确认
L4 发订阅消息通知子女（子女可一键打电话）→ 标记「漏服」→ 结束
```

**级间隔**：每级 10 分钟（STEP_MIN=10），与 v0.3 的 10/20/30 不同。
**短信**：本期不做 L3 短信，触达链路为 L1 → L2 → L4。

#### 短信发送模块（L3）

**本期不做**。sendReminder 中 `sendSMS` 为 TODO 空转，短信兜底已由「L4 电话通知子女」替代。如未来需要自动兜底到老人本人，再接入腾讯云 SMS。

#### 频率「每 X 日一次」处理

frequency 支持「每天 / 每周 / 每 X 日一次」。判断某天是否服药：以 start_date 为锚点，`天数差 % 间隔 === 0` 则为服药日。

#### 续订闭环（一次性订阅）

个人主体只能拿「一次性订阅」模板（授权一次发一条）。三个续订入口：
1. 老人点「已吃药」时同步调 requestSubscribeMessage（无感续订）
2. 老人端/子女端顶部的「订阅状态条」，未开启时点一下授权（断档时手动续）
3. 首次授权时引导勾选「总是保持以上选择」，之后续订不再弹窗

漏服断档（老人不点已吃药 → 额度断）时，靠状态条手动续订 + L4 电话通知子女兜底。

#### 会员订阅（模拟支付）

**开通/续费**：`subscribe` 云函数。点击「开通/续费」→ 更新 `users.subscription_status = 'paid'`、`subscription_expire`。续费逻辑：若仍为有效会员，在原到期日基础上 +30 天；否则从现在起 +30 天。价格 ¥9.9/月。因个人主体无法开通微信支付商户号，采用「点击即开通」模拟支付，未接入真实微信支付。

**会员校验**：各付费功能（周报、打电话）在服务端 / 前端判断 `subscription_status === 'paid' && subscription_expire > Date.now()`。到期自动降级为免费，周报与打电话入口恢复为付费墙。

**付费墙交互**：未付费用户点击周报/打电话 → 弹「开通会员」弹窗（说明 ¥9.9/月）→ 确认后调 subscribe → 刷新页面解锁。

#### 每周用药总结（周报）

`getWeeklySummary` 云函数：先校验会员，未付费返回 `locked: true`。统计老人近 7 天应服/已服/漏服次数与完成率，按「药品 + 时间」聚合漏服分布，构造 prompt 调 DeepSeek 生成一段给子女看的周报。

**周报约束**（SYSTEM_PROMPT）：
1. 只给生活化提醒建议（设闹钟、饭后顺手吃、药放显眼处、午睡后提醒），绝对不说医疗建议（补服/停药/改剂量/换药）
2. 语气温暖、让子女放心，不制造焦虑
3. 指出漏服规律（漏服集中在哪个时间段/哪种药）
4. 无漏服则肯定鼓励
5. 用老人昵称称呼，不用「患者」「您」
6. ≤ 80 字

**护栏**：与 generateText 同一套 —— DANGER_WORDS 硬阻断（停药/停用/减量/加量/增量/补服/换药/调整剂量/加一片/减一片）、纯英文或空输出拦截、标点转中文、超 80 字截断。LLM 失败或连续被拦则走兜底文案（`fallbackSummary`）。
