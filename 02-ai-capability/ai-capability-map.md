# AI 能力分配表

## 设计原则

先规则，后模型。能用确定逻辑的不用 AI，AI 只用在"非它不可"的节点上。

## 功能 ↔ AI 能力映射

| 产品功能 | 是否用 AI | AI 能力 | 具体任务 | 优先级 |
|---|---|---|---|---|
| 药品录入 | 否 | — | 手动输入，结构化表单 | P0 |
| 用药时间表 | 否 | — | 规则引擎，到点触发 | P0 |
| 微信订阅消息推送 | 否 | — | 微信原生 API | P0 |
| 生活化提醒文案生成 | 是 | LLM 文本生成 | 根据药品+昵称+天气/时间生成个性化提醒 | P0 |
| 语音播报 | 是 | TTS 语音合成 | 提醒文案转自然语音 | P0 |
| 食物禁忌提示 | 是 | 知识库 RAG + LLM | DDInter 检索禁忌食物 → 生成通俗提醒 | P1 |
| 用药记录存储 | 否 | — | 数据库 CRUD | P0 |
| AI 拍照识别药盒 | 是（V2） | OCR + 图像识别 | 拍照 → 识别药名和剂量 | P2 |
| 药物冲突自动检测 | 是（V2） | 知识图谱 + 推理 | 多药交叉比对冲突 | P2 |

## AI 能力选型

| 能力 | MVP 方案 | 备选方案 | 选型理由 |
|---|---|---|---|
| LLM 文案生成 | OpenAI GPT-4o-mini / 通义千问 | 本地小模型 | 成本可控，参赛阶段快速验证 |
| TTS 语音合成 | 百度/讯飞 TTS API | OpenAI TTS | 中文语音自然度更高 |
| 知识库检索 | 本地 JSON 导入 DDInter 数据 | 向量数据库 | MVP 数据量小，不需向量检索 |

## 每条 AI 功能的输入输出定义

### 功能 1：生活化提醒文案生成

输入变量：昵称(string)、药品名称(string)、药品类别(enum)、用药时间(time)、用药时机(enum)、天气(string,可选)、特殊禁忌(string,可选)

输出：提醒文案(string，≤80 字，口语化，温暖亲切)

### 功能 2：食物禁忌提示

输入：药品名称(string)、药品类别(string)

输出：禁忌食物列表(string[])、一句话提醒(string)

## MVP 不做 AI 拍照识别的原因

1. 需要大量标注过的药品包装图片（至少数千张）
2. 药品包装频繁换版，模型需持续更新
3. 比赛 MVP 手动录入先跑通，拍照识别作为 V2 亮点
4. 拍照识别有错误率，老年人可能被错误结果误导
