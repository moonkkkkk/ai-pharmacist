# 冷启动策略

## 冷启动要解决的 5 个"零状态"

AI 产品冷启动比传统产品更难——没有数据，AI 就不智能；AI 不智能，就没有用户。

| # | 零状态 | 表现 | 风险 |
|---|--------|------|------|
| 1 | 零用户数据 | 没有昵称、历史记录、行为偏好 | 🔴 高 |
| 2 | 零知识库覆盖 | MVP 仅 50 种药，用户录入的药可能不在库 | 🟡 中 |
| 3 | 零生成样本 | LLM 文案未经真实用户验证 | 🟡 中 |
| 4 | 零语音反馈 | TTS 在老年用户中的接受度未知 | 🟡 中 |
| 5 | 零付费验证 | 不知道子女是否真的愿意付费 | 🟡 中 |

---

## 策略 1：用户数据冷启动——"零输入也能用"

### 信息获取分层

用户给的信息越少，系统越要自己补。设计三层信息获取：

```
Layer 0（零输入，开箱即用）
  → 输入：药品名 + 时间
  → 输出：默认称呼"老人家" + 通用提醒文案
  → 覆盖率：100% 用户立即可用

Layer 1（30秒填写）
  + 昵称 + 服用时机（饭前/饭后/随餐）
  → 输出：半个性化提醒
  → 覆盖率：子女代填，预计 80%+

Layer 2（90秒填写）
  + 药品类别 + 天气感知 + 特殊禁忌
  → 输出：完全个性化提醒（含食物禁忌）
  → 覆盖率：预计 50%+
```

### 缺失信息的默认值

| 缺失字段 | 默认值 | 理由 |
|---------|--------|------|
| 昵称 | "老人家" | 亲切不冒犯 |
| 服用时机 | "饭后" | 多数口服药的安全默认值 |
| 天气 | 不提天气 | LLM prompt 中 weather="" 时跳过天气语句 |
| 禁忌 | 不提禁忌 | 不提好过乱提 |
| 药品类别 | "其他" | 使用通用兜底模板 |

### 首录流程

```
子女扫码 → 输入药品名+时间（必填，30秒）
  → 此时已可生成基本提醒
  → 下一步：昵称+服用时机（选填，30秒）
  → 下一步：药品类别自动匹配知识库
  → 完成，当日即可收到提醒
```

## 策略 2：知识库冷启动——"50 种药覆盖 80% 场景"

### 药品选择原则

- 高频优先：中国慢病老人处方量 Top 50
- 类别覆盖：每个慢病类别至少 3-5 种一线用药
- 禁忌密集优先：优先选相互作用多的药品（AI 价值最大）

### 覆盖预估

| 慢病类别 | 药品数 | 预计覆盖 |
|---------|--------|---------|
| 高血压 | 12 种 | ~85% |
| 2型糖尿病 | 8 种 | ~90% |
| 高血脂 | 5 种 | ~80% |
| 冠心病/抗凝 | 5 种 | ~75% |
| 骨质疏松 | 3 种 | ~70% |
| 其他（痛风/甲减/前列腺等） | 17 种 | ~60% |

### 未命中药品处理

```
用户录入药品 → 查知识库
  ├── 命中 → 正常（含禁忌提示）
  └── 未命中 → 降级模式：
       ├── 提醒功能不受影响
       ├── 食物禁忌提示暂不可用
       ├── 药品加入"待补充清单"
       └── 每周统计 Top 10 高频未命中，优先补充
```

降级不降体验：LLM 本身了解常见药，未命中药物的提醒文案仍可 AI 生成。

## 策略 3：AI 文案质量冷启动——"先用模板，AI 平行跑"

### 第一周：AI 不直接面向用户

```
提醒触发
  ↓
优先用预设模板（100% 安全）
  ↓
同时后台跑 LLM 生成 → 人工抽查 → 积累质量基线
```

### 渐进放量

| 阶段 | AI 文案展示比例 | 放量条件 |
|------|--------------|---------|
| 第一周 | 0%（平行观察） | — |
| 第二周 | 30% | 护栏拦截率 < 5% |
| 第三周 | 70% | 人工评审通过率 > 90% |
| 第四周 | 100% | 药品名准确率 > 99.5% |

## 策略 4：用户获取冷启动——"从 10 个家庭开始"

```
第0步：团队内测（上线前 1 周）
  → 团队成员的父母先试用
  → 目标：发现最严重的体验问题

第1步：种子用户（10-20 个家庭）
  → 来源：朋友圈 + 社区老人中心 + 病友群
  → 当面帮老人设置，非线上投放
  → 目标：第一周真实数据

第2步：口碑传播（50-100 个家庭）
  → 子女推荐给其他子女
  → 验证自然传播意愿

第3步：比赛后决定是否规模投放
```

### 种子用户选择标准

- 慢病老人（≥2 种慢病）
- 子女异地（子女端价值最大）
- 老人会用微信（降低门槛）
- 子女愿意给反馈

## 策略 5：付费冷启动——"30 天免费 + 软着陆"

```
注册 → 30天全功能免费试用
  → 到期前 3 天提醒
  → 付费：月付 ¥9.9/月 | 年付 ¥99/年（¥8.25/月）
  → 不付费 → 降为基础版（仅用药提醒，无 AI 文案/禁忌/子女通知）
```

### 定价锚点

- ¥9.9/月：一杯奶茶换一个月的安心
- vs 智能药盒 ¥150-500：连零头都不到

## 冷启动成功标准

| 阶段 | 时间 | 目标 | 衡量 |
|------|------|------|------|
| 内测 | 上线前 1 周 | 产品可运行 | 3 个家庭成功收到提醒 |
| 种子用户 | 上线后 1-2 周 | PMF 信号 | 20 个家庭，D7 留存 ≥ 70% |
| 初步验证 | 上线后 3-4 周 | 付费验证 | 5 个付费家庭 |
| 比赛提交 | 上线后 4-6 周 | 数据支撑 | 可展示真实留存率和用户反馈 |

## 最大风险与应对

| 风险 | 概率 | 应对 |
|------|------|------|
| 老人关掉微信通知 | 高 | 语气温柔、频次可调、允许"今天不想被提醒" |
| 子女不帮老人设置 | 中 | 设置流程 ≤ 60 秒，支持远程帮老人设置 |
| AI 文案质量波动 | 中 | 护栏兜底 + 渐进放量 |
| 试用到期无人付费 | 中 | 若 0 付费，比赛前调整为免费+增值模式 |
| 微信订阅消息限制 | 低 | 提前验证发送频次和模板审核规则 |

---

## 三条原则

1. **零输入也能用** — 不依赖用户数据，第一天就有基本体验
2. **渐进式收集** — 用户多给一点信息，体验好一点，不给也不差
3. **模板兜底 AI** — AI 提高上限，模板保证下限
